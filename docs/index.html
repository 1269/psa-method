Everything you own is a project, a system, or an archive.

PSA is a systems-first productivity method your AI agents can run with you: ongoing systems maintained through automated process, finite projects that serve them — in plain folders and plain markdown, mirrored across every tool you use, so an agent can navigate your working world without guessing.

Three stages, and nothing in between

Every file, note, task, and journal entry you own sits in exactly one lifecycle stage. That single rule is the whole method, and it’s why an agent can find anything of yours without hand-holding.

Projects1_Projects/

Outcome-driven work — as many steps and phases as it takes, but it ends. Every project has a goal, a plan, and a system it serves, written down in a Brief your agents read too.

Systems2_Systems/

The method’s center of gravity: ongoing areas of responsibility with no end date — content, finance, health. Systems don’t finish. They’re maintained through automated process and reviewed on a cadence.

Archives3_Archives/

Completed and retired work, kept for recall and reuse. Nothing is deleted; finished projects land here with their briefs and learnings intact.

Focus by design A hard cap on active projects: 8 to 15, you pick. New work requires finishing old work.
“Every project ends deliberately: archived, or converted into a system. Finished work leaves behind infrastructure, not clutter.”
the PSA lifecycle rule

Four spaces, one shape

A space is any tool that mirrors the Projects / Systems / Archives structure. PSA doesn’t replace your tools. It gives them all the same spine, so you (and your agents) always know where a thing lives.

File Share working

Code, assets, production files.

Second Brain thinking

Briefs, notes, learnings, task files, always local markdown.

Task Manager doing

Next actions, recurring maintenance.

Journal capture

Raw thoughts and daily entries, before processing.

Plus a calendar. Not a space, but PSA-aware: it schedules ready work into your available time blocks.

Bring your own tools. Any task manager (OmniFocus, Things, Todoist, Asana, or none). Any journal. Any calendar. The skill automates what it can and guides you through the rest.

Agent-ready by construction

Briefs, indexes, and task files are markdown with a small, stable contract. Your agents read the same files you do: no export, no sync, no vendor API between you and your own notes. One command, /psa add-context, expands any task into a self-contained brief an agent can execute cold.

# Brief.md, every project gets one (GPS framework)

Goal     What you're building, why it matters, what done looks like
Plan     Key milestones, time commitment, dependencies
System   How progress is tracked, where tasks live
Safe by default PSA never deletes. Every command that writes shows you the full plan and waits for a yes.
See the file contract in the repo

Install in three commands

  1. Get the skill

    Requires Claude Code. PSA installs as a personal skill, available in every project.

    git clone https://github.com/1269/psa-method.git
mkdir -p ~/.claude/skills
cp -r psa-method/skills/psa ~/.claude/skills/psa

  2. Run setup

    Restart Claude Code, then let setup interview you: where your files, notes, tasks, journal, and calendar live, and your project cap. One config file, all four spaces scaffolded.

    /psa setup

  3. Run your day with it

    The same command is the daily driver: status, capacity, reviews, new projects, archiving.

Existing mess welcome Setup only creates missing folders. It never moves or renames anything you already have.
/psa

Status: capacity, projects, systems needing review, task pipeline.

/psa new

Create a project across all spaces, capacity-gated, with a Brief.

/psa review

7-point health check: capacity, stale briefs, orphans, drift.

/psa archive

Close a finished project into Archives.

/psa convert

Turn a finished project into an ongoing System.

/psa add-context

Expand a task into a brief an agent can execute cold.

Twelve commands in all: the full table is in the README.
